# ADR-0002: Build on Next.js 16, not the spec's Next.js 15

**Status:** Accepted
**Date:** 2026-08-06
**Amends:** SPEC.md §2 (stack table)

## Context

SPEC.md §2 pins "Next.js 15, App Router, TypeScript" and marks the whole stack
table "(fixed, do not substitute)". Scaffolding with `create-next-app@latest`
installed **Next.js 16.3.0** with React 19.2.8 — 16 is now the current stable
release.

Downgrading to 15 is possible but costs time and pins the project to an older
line for the rest of its life.

## Decision

Stay on Next.js 16.3.0.

## Rationale

The spec names 15 because that was current when it was written, not because
anything in the build depends on 15-specific behaviour. Every Next feature this
project actually relies on is present and stable in 16:

- **App Router** — unchanged, and what §10.3's route structure assumes.
- **`after()`** — stable since 15.1, still stable in 16. Note that ADR-0001's
  decision to run extraction inline means the webhook path does not depend on
  it; it remains available for the manual-retry route in SPEC.md §5.
- **`output: "standalone"`** — verified working. `.next/standalone/server.js` is
  produced, which is what the Dockerfile in ADR-0001 copies.

A production build was run and passed before this ADR was written, so the
version choice is verified rather than assumed.

## Consequences

- SPEC.md §2's "do not substitute" rule is relaxed for this one row. The rest of
  the stack table stands.
- Turbopack is the default build engine in 16. Build output differs cosmetically
  from 15's webpack output; nothing downstream reads it.
- shadcn/ui and Clerk both need to be confirmed compatible with Next 16 + React
  19 at install time. If either turns out to be blocked on 16, that is the
  trigger to revisit — see below.

## Revisit if

- Clerk or shadcn/ui cannot install cleanly against Next 16 / React 19.
  Downgrading to 15 at that point is a `package.json` change plus a reinstall,
  and no application code written so far would need to change.

## Outcome (2026-08-11)

Both trigger conditions cleared; this ADR is settled.

- **shadcn/ui** installed and was restyled against the tokens in the app-shell
  work.
- **Clerk** installed as `@clerk/nextjs@7.7.3`, whose `next` peer range names
  `^16.1.0-0` explicitly. Its one Next-16-specific consequence is the file
  name: Middleware is called **Proxy** in 16, so `clerkMiddleware()` is exported
  from `proxy.ts` rather than `middleware.ts`. The function itself is unchanged
  — it returns a standard `(request, event)` handler, which is what the new
  convention expects.
